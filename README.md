# 찍계부 PWA 프로토타입

## v1.0.3 엑셀 가져오기

홈 화면에서 **카드 엑셀 등록**을 눌러 XLS/XLSX 파일을 선택합니다. 카드사와 연도를 확인하고 **선택한 설정으로 내역 읽기 → 등록 전 확인 → 이대로 등록** 순서로 사용합니다. 한 번에 한 파일·한 시트를 가져옵니다. 파일 크기는 20MB, 시트 행 수는 10,000행 이하입니다.

- 주·월 구간 제한 없이 실제 이용일로 월별 합산합니다. 연도 없는 날짜는 선택한 연도로 적용하며, 12월과 1월이 섞인 연도 없는 파일은 분리를 요청합니다.
- 우리카드 2단 명세서 열을 자동으로 연결합니다. 국민카드의 일반적인 이용일·가맹점·금액 등 열 별칭도 지원하며, 다른 형식은 ‘열 연결 확인’에서 직접 지정합니다. 실제 KB 내보내기 양식은 아직 미검증입니다.
- 소계와 합계는 거래에서 제외합니다. 할인과 청구원금을 별도 보관하고, 일시불의 금액이 맞지 않으면 등록을 막고 확인을 요청합니다. 할인 정보가 없는 파일은 ‘미확인’으로 표시합니다.
- 동일 파일·시트의 재등록을 차단합니다. 다른 파일에 겹친 거래는 발생 건수만큼 대응시키며, 승인번호로 확실히 일치하는 동일 거래만 자동 제외합니다. 승인번호가 없거나 할인 등이 바뀌면 ‘기존 거래 / 새 거래 / 기존 거래 갱신’을 선택합니다. 행의 순서나 같은 금액만으로 반복결제를 삭제하지 않습니다.
- 미분류 업체 버튼으로 동일 업체 전체를 선택한 후 한 번에 분류할 수 있습니다. 사용자 분류는 같은 브라우저에 저장됩니다.
- 취소는 별도 음수 거래로 반영합니다. 할부의 전체 이용금액은 이용월 소비에, 청구원금은 카드별 결제대금에 표시합니다. 청구월이 없는 거래는 다음 달 14일 결제 예상으로 표시하고, 명세서 청구월이 지정되면 그 월을 우선합니다. 업로드 내역의 일부 합계일 수 있으며 카드사의 확정 명세서를 대체하지 않습니다.
- 엑셀 내용은 브라우저 안에서만 처리합니다. 처음 읽을 때 공식 SheetJS CDN에서 0.20.3 읽기 도구를 내려받으므로 인터넷 연결이 필요합니다. 사진 OCR은 접힌 보조 메뉴로 유지합니다.

검증: `node --test --test-isolation=none tests.cjs excel-tests.cjs` (21개). 실제 우리카드 XLS 파싱·합계와 브라우저 등록을 확인했습니다. 합성 XLSX로 월 경계, 승인번호 중복, 할인 갱신 흐름을 확인했습니다. 저장소에는 실제 이용내역 파일이나 개인정보를 포함하지 않습니다.

변경 파일: `excel-core.js`(열·날짜·금액 정규화 및 중복 비교), `excel-ui.js`(업로드·검토·저장·카드별 결제), `app.js`(분류 및 기존 검토 연동), `index.html`, `styles.css`, `sw.js`, `excel-tests.cjs`.

## v1.0.2 변경 사항

- 최상단에 현재 버전 표시. 다음 변경 묶음에서는 `node bump-version.cjs`를 한 번 실행하면 앱·HTML·서비스 워커의 patch 버전이 함께 올라갑니다.
- 카드 이미지 비교를 제거하고 `본인 0322`, `본인 9569`의 끝 4자리를 문자열로 보존합니다. 인식하지 못한 카드는 검토 화면에서 확인합니다. 같은 끝자리 카드의 이름은 브라우저에 저장됩니다.
- `원`이 붙은 결제금액만 거래로 추출하고, `할인 N원`은 같은 결제 행에 별도 연결합니다. 할인액이 결제액보다 크거나 여러 개면 확인 표시를 합니다. 색상 자체가 아닌 OCR 문구와 위치를 사용합니다.
- 우아한형제들→배달음식, 지에스차지비→전기차 충전 등 확실한 규칙만 자동분류합니다. 플레이타임과 불확실한 업체는 미분류로 두고 선택/일괄분류를 제공합니다. 수동 분류는 동일 브라우저에 기억합니다.
- 조회 월별 총 사용금액, 받은 할인, 최종지출을 표시합니다. 과거 데이터에 할인 필드가 없으면 0원으로 계산합니다.
- 기존 거래 저장 키 `jjig_txs`는 유지합니다. 기존 카드 이미지 데이터는 삭제하지 않지만 새 인식에 사용하지 않습니다.

## 개발 및 검증

- 실행: `node serve.cjs` → `http://127.0.0.1:4173`
- 자동 테스트: `node --test --test-isolation=none tests.cjs`
- 개발 서버의 `/review-test`는 가상 OCR 데이터로 검토 UI를 시험하는 전용 경로입니다. 운영 페이지에는 테스트 데이터가 들어가지 않습니다.
- 자동 테스트 8개: 통화 단위, 카드 끝자리, 할인 연결, 좌표/중첩 블록, 반복 소액결제, 기존 데이터 집계, 매핑 저장, 버전 일치 등을 검증합니다.
- 브라우저에서 미분류 2건 일괄 변경, 새로고침 후 분류 기억, 총 22,000원 − 할인 3,975원 = 최종 18,025원을 확인했습니다.
- 실제 카드 스크린샷 파일은 제공되지 않아 실제 이미지→문자 인식 정확도는 미검증입니다. OCR 텍스트 및 좌표 fixture와 UI를 검증했습니다.

## 배포 상태

이 버전은 GitHub `wh101f-coder/jjikgyebu`의 main에 반영해 GitHub Pages로 배포합니다. 동일 주소에 배포하면 기존 홈 화면 아이콘을 유지할 수 있고, 앱을 다시 열었을 때 헤드라인의 버전으로 확인할 수 있습니다. 업데이트 적용 시점은 브라우저의 서비스 워커 갱신 시점에 따라 달라질 수 있습니다.

아이폰에 앱처럼 설치할 수 있는 웹앱(PWA) 버전입니다.

## 지금 들어있는 기능
- 카드 사용내역 스크린샷 여러 장 선택
- 한국어/영어 OCR
- 날짜 / 업체명 / 금액 / 카드사 후보 추출
- 연속 스크린샷의 겹친 거래를 보수적으로 중복 제거
- 동일 날짜·동일 업체 반복 소액결제를 합계로 묶어서 표시
- 등록 전 수정
- 지출 직접 등록 / 수정 / 삭제
- 월별 합계 / 전월 비교
- 기본 소비 분석
- 모든 지출 데이터는 현재 브라우저의 localStorage에 저장

## 중요
이 프로토타입은 OCR을 위해 Tesseract.js와 한국어 OCR 모델을 인터넷에서 불러옵니다.
처음 분석할 때 시간이 조금 걸릴 수 있습니다.

카드앱마다 화면 구성이 달라서 첫 버전 파서는 범용 휴리스틱입니다.
실제 카드앱 스크린샷을 테스트하면서 카드사별 파서를 추가하면 정확도가 크게 좋아집니다.

## Windows에서 가장 쉬운 배포: GitHub Pages
1. GitHub에 로그인
2. 새 Repository를 만들기 (예: jjig-ledger)
3. 이 폴더 안의 파일들을 전부 업로드
4. Repository → Settings → Pages
5. Build and deployment에서 "Deploy from a branch"
6. Branch를 main / root로 선택하고 Save
7. 잠시 후 표시되는 https://아이디.github.io/jjig-ledger/ 주소를 아이폰 Safari에서 열기
8. Safari 하단 공유 버튼 → "홈 화면에 추가"
9. 홈 화면의 '찍계부' 아이콘으로 실행

## 다른 무료 호스팅
Netlify Drop, Cloudflare Pages, Vercel 등 정적 사이트 호스팅에도 그대로 올릴 수 있습니다.

## 개인정보
현재 버전은 OCR을 브라우저 안에서 수행합니다. 지출 데이터는 외부 서버 DB에 저장하지 않습니다.
다만 Tesseract 라이브러리/언어모델 파일을 CDN에서 다운로드합니다.
